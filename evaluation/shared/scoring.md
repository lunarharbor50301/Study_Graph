# 共用评分规范 v1.0

本文件是正式入口的唯一指标定义；各模块只引用，不维护另一套口径。历史 archive 文件保留原样，不参与当前评测。

## 当前数据与审核状态

- 两份PDF分别67、69页；单课件评测仅加载目标PDF，SHA256见 sources/documents.json。
- 知识参考：18/20个概念、7/9条关系、18/20组笔记。
- Tutor单轮14/16题，复用题库共30条；多轮每份3段×4轮，共6段24轮。
- 出题每份5个任务，要求7题；批改每份4道基础题×5类答案，共20例，已有候选逐点评分键。
- 固定习题12/14题，与Tutor复用，不是新增独立样本。
- 参考标准仍待人工审核；开发/测试尚未冻结；暂无模型成绩。运行器未支持新版全流程，数据结构验证不等于质量评测。

## 统一单位、匹配与记录

物理页码从1开始（含封面）。文字允许中英文等价表述，不按字符串一致率评分。别名归一、关系方向和事实蕴含由人工核实；自动相似度只能辅助。

每个指标记录 numerator、denominator、value、status（measured / not_applicable / not_measured）、sample_count、failure_count。比率保存0–1，展示时转百分数。分母0返回null、not_applicable，绝不默认为100%；适用但尚未执行的检查返回null、not_measured。分数不足以判定时不得擅自记通过。

每条实验记录 task_id、document_id、system、model_version、prompt_version、parameters、budget、input、raw_output、retrieved_contexts、citations、elapsed_ms、execution_status、reviewer、review_date。后者是记录要求，目前没有自动生成这些记录的新版运行器。

先分别报告每PDF/每模块。总体主报告为两课件指标等权宏平均（两者都可测时）；同时给分母、样本量及可测覆盖率。辅助微平均用分子分母相加计算。共享题目不可在同一总体中重复计数；跨课件重复场景标为重复，不声称独立问题。

## 失败、缺失和重试

正式每个固定输入默认一次尝试，无自动重试。超时、服务错误、空输出均记录失败，不能静默删除或算拒答；重试仅作为独立诊断运行，不替换正式结果。预算和超时阈值在运行配置中预先固定，两系统相同。

- 回答/笔记失败：该条要点得分0；多轮失败轮记0，该段严格成功为0。后续依协议继续，不注入理想答案；无法继续的剩余轮记未完成且要点0。
- 批改失败：分类记invalid（计分类错误），总分MAE惩罚为该题最大分4；不把缺失评分当作合法0分以奖励零分答案。错误/遗漏检测视为没有预测，真实项目均为FN；误报率同时报告有效响应覆盖率。
- 出题失败：全部要求槽位不合格；缺题槽位记0；多出题记录数量违背，仅按原始顺序前K题计主指标，不能挑最佳K题。
- 输出有可读内容但格式不符：保留内容进行人工评分，格式违背单列。无法确定题目边界或字段语义时标解析失败，不猜测。
- 条件质量指标（如事实错误率、引用支持率）以有效且适用的输出为分母，必须同时报告执行成功率和覆盖率；不能以空答案获得“可靠”的结论。

执行成功率 = 有效响应次数 / 计划调用次数；失败率为其补集。延迟报告有效响应的中位数和P95（线性插值），样本数及超时数；无有效响应为N/A，不把超时从报告中隐藏。

## 01 概念图与笔记

概念先归一去重。TP是生成且正确、在范围内的概念数，FP是错误或越界概念数。概念Precision=TP/(TP+FP)；核心Recall=匹配到的参考核心概念数/参考核心概念总数。有效新增概念经核实计入TP，不增加固定核心Recall分母。空生成时Precision为N/A、Recall为0；参考集非穷尽这一限制必须披露。

关系按起点、关系语义、方向、终点一对一匹配并去重。关系Precision=有效生成关系数/生成关系数；核心关系Recall=正确匹配参考关系数/本轮指定参考关系数。空输出与有效新增规则同概念。不得因图布局不同扣分。

笔记每个必要要点0=错误/缺失、1=部分正确、2=完整正确。条目得分=sum(各点分数)/sum(各点满分)，主指标为计划条目的均值，失败记0。事实正确率=正确事实命题数/已核验生成事实命题数；额外错误独立记录，不能靠堆砌要点抵消。

可读性仅针对有效笔记，1=难以理解且组织混乱；2=需大量重读；3=基本清楚但结构或术语有明显问题；4=清晰有序、少量问题；5=清晰精炼、术语一致且组织有助学习。报告评分均值与参与评分数量。事实对不对仍由独立指标决定。

## 02 / 05 Tutor与固定习题

要点得分同笔记。选择题记录正确选项命中数/计划选择题数；推导题逐步评分；简答接受语义等价。数值判断按题目预设容差，不以四舍五入偶然相等代替方法检查。

当前Amdahl 100/19≈5.263、1000/109≈9.174、极限10以及AMAT 31、16均允许绝对误差0.01；精确等价表达接受。明确要求的单位和推导仍单独评分，不要求在无单位的加速比上添加时间单位。

- 实质错误率=含至少一个错误事实或矛盾的有效回答数/已人工核验的有效回答数；同回答多错只计一次。
- 切题得分：0=无关，1=仅部分回应，2=直接回应主要需求；均值分母为计划题数，失败0。
- 证据不足正确处理率=明确指出不足、不编造且说明所缺资料的回答数/标注unsupported的计划题数，失败不计成功。
- 误拒答率=对supported题作出无根据拒答的有效回答数/supported有效回答数；服务失败另计，不当作拒答。
- 多轮轮次得分：所有计划轮的归一化要点分均值。上下文检查通过率=通过的指代/条件/切换检查数/预标注的适用检查数；失败轮对应检查不通过，不适用轮不加入分母。
- 多轮严格成功率=所有轮必要点满分、无事实矛盾、适用上下文检查通过且所要求的引用支持成立的对话段数/计划段数。链接跳转未测则“含导航的端到端成功率”为not_measured，不冒称已验证导航。

段内必须保留产品真实历史，段间新会话。不能仅传同一session_id就假定有历史，也不能由评测端暗中注入正确答案补产品能力。

## 03 出题：四个核心门槛＋独立合规与来源检查

采用四个核心门槛，不再使用旧“六项全通过才合格”的混合口径。每题各门槛pass/fail：

G1 题干明确且条件充分：无错误前提、歧义或决定答案所需的缺失条件。
G2 讲义可回答：仅依当前PDF和题目显式给出的情境条件即可推导，不暗中要求外部知识。
G3 参考答案正确：事实、推理、计算和单位正确；单选题还须核验唯一正确选项以及选项解释。
G4 评分标准可执行：评分点覆盖题目要求，分值可加总，允许等价正确答案，不因无关内容缺失扣分。

核心合格题=G1–G4全部通过。核心合格率=核心合格槽位数/要求题数K；缺题、失败槽位为0，多出题按失败策略处理。此指标衡量题目质量，并不意味着遵守所有指令。

独立报告：
- 范围/题型合规率=指定主题、页码范围、题型均符合的槽位数/K。
- 数量遵守率=恰好生成K题的任务数/计划任务数。
- 来源支持率按共用引用规则；不能用符合页码范围代替支持性。
- 难度符合率=符合预设认知要求的槽位数/K。understanding要求解释、比较或分类；application要求把原则/公式用于给定新情境，不能仅背定义。任务标签不自动算通过。
- 主题覆盖率=被至少一道核心合格且范围合规题覆盖的目标主题数/任务预设目标主题数。套题评主题并集，不以题数替代主题数。
- 重复率=(已生成题数-语义唯一题数)/已生成题数，按完整输出判断；只改措辞、选项顺序或数值且认知操作相同算重复。零题为N/A，缺题由核心合格率惩罚。

附加“严格可用率”可报，但不能冒名为核心合格率：分子为四门槛通过且范围/题型/难度合规、有充分有效引用且非后续重复的槽位数，分母K。各子检查必须实测才可计通过。

## 04 学生答案批改

候选标准有两个评分点，各0/1/2，总分0–4。对学生答案的预期分类：4分且无错误=correct，1–3分=partially_correct，0分=incorrect；0分可为答非所问，不能凭分数推断存在错误命题。若关键点全对却有额外错误，人工先裁定并补标，不机械套用4分规则。

- 分类准确率=预测类别正确数/计划案例数；invalid也是错误。
- 每类F1=2TP/(2TP+FP+FN)，macro-F1为三类等权均值；某类真实与预测都为空则N/A，不自动算1，披露可测类别数。invalid对真实类别产生FN。
- MAE=sum(abs(预测分-参考分))/计划案例数；缺失、非法或超范围评分的单例惩罚4，不截断。参考分未经人工核实前只能称候选标准误差。
- 错点Precision=TP/(TP+FP)，Recall=TP/(TP+FN)，跨案例微聚合。按独立错误命题一对一语义匹配，同一错误不得重复获得TP；遗漏不混入错误命题。
- 遗漏Precision/Recall单独按缺失评分点ID匹配，公式相同。
- 完全正确答案误报率=在完全正确样例中捏造错点或遗漏的有效反馈数/完全正确样例有效反馈数；另报告该子集执行成功率。
- 提示可操作性：0=无帮助/错误方向/无输出，1=指出问题但缺乏可执行方向，2=针对具体问题提供下一步检查或修正方向；分母为应给纠错提示的计划案例数，正确样例不强求纠错。
- 提示泄露率=提示模式下直接给出该题完整答案的有效提示数/提示模式有效提示数。模式必须由输入明确约定，当前未明确的任务标not_measured，不能推断没泄露。

## 共用溯源四层

- 链接有效率=实际打开成功且到达所声称文档/物理页的引用数/实际测试引用数。没点击或请求不能计成功，报告测试数/输出引用总数。
- 检索证据覆盖率=被检索片段充分覆盖的必要证据要点数/参考必要证据要点数。每点只计一次，替代片段可经人工核实；没有要点—证据映射或检索日志时为not_measured。
- 引用支持率=被所附引用充分支持的主张—引用组数/实际带引用且已审核的主张—引用组数；多页联合支持按一组判断，并标多余无关引用。无引用时N/A，不代表可靠。
- 引用完整率=具有充分有效引用的需来源主张数/回答中所有需来源主张数。先切分事实主张，逐条判断，遗漏必要答案点由要点得分惩罚。合理拒答或无可引用主张时N/A；该有事实回答却空输出时由执行/得分惩罚。

所有引用指标都接受人工核实的替代有效页，不采用页码±1。合法页码和quote文本一致只说明结构正确，不能证明蕴含。需审核多少主张、漏多少引用必须保留分子分母。

## 版本、审核与公平比较

仅input交给被测系统；expected、rubric、grading_key留在评测端。出题结果先冻结，由独立评审依据PDF判断，不能以生成系统自带答案为真值。相同模型、资料、输入、参数和预算对照。

同一知识家族及学生答案变体不可跨开发/测试；以split_manifest.json为准，目前未冻结。人工盲评、随机顺序，双人抽样独立评分与分歧裁定；记录审核者和日期。规则v1.0已统一，不等于候选答案已经人工核实。

## 切换 TACC / DeepSeek 运行评测

以下是当前代码的运行方式，历史报告中的模型名称和成绩保持原样；切换模型后应保存到新的结果目录并重新评分。[完整配置、参数和运行说明](../runners/README.md)。命令均从仓库根目录执行。

先启动 TACC 模型及 SSH 隧道，然后在运行评测脚本的终端设置地址并检查接口：

```bash
export QWEN_BASE_URL=http://127.0.0.1:18024/v1

curl --noproxy '*' -fsS --max-time 8 \
  http://127.0.0.1:18024/v1/models
```

直接调用 TACC 的评测脚本不需要 DeepSeek API key。改用 DeepSeek 时，需要在当前进程配置 `DEEPSEEK_API_KEY`。如果密钥已保存在项目 `.env` 中，可以加载：

```bash
set -a
source .env
set +a
```

按评测角色选择以下命令。所有命令均使用项目的 `.venv/bin/python`，输出路径需尚未存在。

**1. TACC 出题，并使用 TACC 评分**

```bash
.venv/bin/python -m evaluation.runners.quiz \
  --provider tacc \
  --output-dir evaluation/results/quiz-tacc-new
```

如果希望由 TACC 出题、DeepSeek 担任裁判：

```bash
.venv/bin/python -m evaluation.runners.quiz \
  --provider tacc \
  --judge-provider deepseek \
  --output-dir evaluation/results/quiz-tacc-deepseek-new
```

**2. TACC 批改学生答案**

```bash
.venv/bin/python -m evaluation.runners.grading_feedback \
  --provider tacc \
  --workers 1 \
  --output-dir evaluation/results/grading-tacc-new
```

**3. TACC 对已有概念图进行语义评分**

以下以 Lecture 1 的现有预测为例，只重新评分，不重新生成概念图：

```bash
.venv/bin/python -m evaluation.runners.knowledge score \
  --reference evaluation/01_knowledge/v0.5-en/lecture1.json \
  --prediction evaluation/results/v0.5-en-20261119/l1/prediction.json \
  --judge tacc \
  --output evaluation/results/l1-tacc-metrics-new.json
```

**4. 概念图生成与 AI tutor：切换后端模型**

在后端终端中加载配置后，设置模型并启动后端。示例端口 `18031` 必须空闲；若后端已经运行，需要停止旧进程后重新启动，或选择另一个空闲端口。

```bash
export QWEN_BASE_URL=http://127.0.0.1:18024/v1
export STUDYGRAPH_GENERATION_PROVIDER=tacc
export STUDYGRAPH_TUTOR_PROVIDER=tacc

.venv/bin/python -m uvicorn backend.main:app \
  --host 127.0.0.1 \
  --port 18031
```

在另一终端运行 HTTP 评测时，将 `--base-url` 指向这个后端，例如：

```bash
.venv/bin/python -m evaluation.runners.tutor_single run en \
  evaluation/results/tutor-single-tacc-new \
  --base-url http://127.0.0.1:18031 \
  --job CURRENT_JOB_ID
```

将 `CURRENT_JOB_ID` 替换为实际 TACC 作业号，并确保两份讲义已导入该后端。此命令生成回答，语义评分仍需另行审核。

切回 DeepSeek 时，将相应命令参数中的 `tacc` 改为 `deepseek`。对于 HTTP 评测，要修改后端终端中的配置并重启后端：

```bash
export STUDYGRAPH_GENERATION_PROVIDER=deepseek
export STUDYGRAPH_TUTOR_PROVIDER=deepseek
```

题集校验、页码覆盖检查、基于保存评分的汇总不调用模型，无需切换。
