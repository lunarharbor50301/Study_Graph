# StudyGraph 概念图组会讨论稿
2026-11-18 · Lecture 2 首轮结果与下一轮实验决策

**这次生成的 20 个节点都被评分器判为有效，但按 v0.4-en 参考集，覆盖了 20 个核心概念中的 8 个。** 组会最值得先回答的问题是：漏掉的概念在上传后有没有被读到？有没有进入模型实际看到的摘录？如果已经进入，为什么没被选为节点？

## 首轮实验测到了什么

一次生成，模型为 DeepSeek Flash，使用默认的整份讲义学习指南要求，输出 20 个概念节点。以下结果采用 v0.4-en 参考集，作为后续修改的基线。参考集仍待人工复核。

| 指标 | v0.4-en 基线 |
|---|---:|
| 核心概念覆盖率 | 8/20（40%） |
| 生成节点准确率（Precision） | 20/20（100%） |
| 图内笔记得分，按参考笔记等权平均 | 34.17% |
| 图内笔记累计得分 | 36/104（34.62%） |
| 完全覆盖的笔记要点 | 15/52（28.85%） |

笔记得分只覆盖生成概念图时附带的笔记。点击单个概念后另行生成的流式笔记尚需单独测量。[实际模型与输出](../evaluation/results/l2-run1/prediction.json) · [v0.4-en 评分明细](../evaluation/results/l2-run1/v04/metrics.json)

## 一次点击实际做了什么

1. 前端等待课件上传或复用已入库文档。后端从有文字的页面中均匀抽取最多 32 页，每页取前 700 个字符，再用学生要求做本地全文检索，最多补 8 个片段，按页码合并。60 个有文字的页面中，只有 32 个进入均匀抽样；检索命中页可能重合。
2. 后端把摘录和学生要求一次发给模型。TACC Qwen 和 DeepSeek 共用提示词，关闭思考，温度为 0，输出上限 4400 tokens。概念图没有 Agent 循环或模型自主调用工具。模型同时写主题、节点、摘要、详解、要点、公式与引用页码，最多 5 个主题、每主题 4 个概念。
3. 完整 JSON 返回后，后端校验字段与页码，前端组图。产品保留主题与概念的从属结构。概念间语义关系已移出产品范围，旧评测中的关系指标仅作历史记录。[后端生成](../backend/study_guide.py) · [前端组图](../frontend/src/slideOutline.ts)

**模型切换与效率。** 概念图、单概念笔记和出题共用环境变量 STUDYGRAPH_GENERATION_PROVIDER，设为 deepseek 或 tacc 后重启后端；缺省走 TACC。想让图和笔记分别使用不同模型，需要拆开配置。AI 助教另走 TACC；离线评分器也可独立选择 DeepSeek。当前只有 DeepSeek 的这份图，没有同条件的 TACC 点击到完整图可用耗时。TACC 配置 SSH 网关时每次请求会启动 SSH，实际速度还取决于排队、输入输出长度及推理时间。[模型配置](pi-agent.md) · [TACC 客户端](../backend/qwen_client.py)

## 哪些改动值得试

- **选材和图片。** PPTX 可提取文本框和表格，PDF 优先读取文字层。预览能显示图片，概念图模型只收到文字。配置 OCR 后，PDF 目前只对完全没有文字的页做整页识别。一页若只有可编辑标题和一张架构图，可能只留下标题。建议先对照原页、解析文本和模型摘录，定位漏点。对 40–60 页讲义按文本预算决定是否送全文；超预算时按章节分配空间，兼顾学生重点。如果后端能一次收集好这些材料，可直接改代码。只有需要模型按缺口主动补读时，才引入 read_pages 工具。[解析与 OCR](../backend/documents.py)
- **OCR 成本。** 全页本地 OCR 会增加首次上传解析时间，本身不消耗模型 token。模型成本取决于最终送入的文字量。可先比较当前解析、仅对含图页补 OCR、逐页 OCR，记录耗时及新增的有效概念证据。复用已入库文件会跳过解析，比较前应确保实际重新解析。箭头、拓扑和趋势仍需单独验证，识别出标签并不足以恢复关系。
- **提示词与稳定性。** 已明确选取实质讲解的概念、合并同义词、按讲解顺序组织、让详解和要点有页内依据，也细化了单概念笔记要求。温度为 0 不能解决“哪些算核心”的判断差异。这次提示词调整尚无真实讲义的前后对照。先固定生成次数及配置，记录多次生成的核心概念命中情况。[概念图提示词](../backend/study_guide.py) · [单概念笔记](../backend/study_notes.py)
- **校验放在哪里。** 线上保留现有结构和页码检查。拟议的 validate_map 放在离线评测：对照独立参考集核覆盖，对照原页核事实与引用，统计近义重复和笔记要点。对自动判分的争议项保留人工复核。它不能仅靠查看生成结果发现遗漏主题。

## 建议组会敲定的三件事

1. **先定位漏点。** 按 v0.4-en 参考集逐一检查漏掉的 12 项，标记“解析缺失”“已解析但未送入”“已送入但未生成”或“评分口径待复核”，再决定优先改 OCR、选页还是概念筛选。
2. **确定产品边界。** 20 个节点是有意的阅读上限，还是可按讲义规模调整？这项决策会影响覆盖率上限和阅读负担。
3. **分别比较质量与速度。** 固定参考集、讲义、提示词和输入摘录，两家模型各重复生成；记录覆盖率、准确率、引用支持度、节点数、失败次数和点击到首个完整可交互图的耗时。首次上传和文档已入库分别报告，另记模型请求耗时与输出长度。比较选材或 OCR 时固定模型，一次只改变一个因素。
