# StudyGraph 检索与模型工作计划

真实模型联调后的开发顺序、团队交接和验收方式见 [下一阶段开发计划](next-development-plan.md)。

**第一周的交付是一条真实讲义问答。** 学生选中一个概念或直接提问后，后端能从讲义找到原文，让 Qwen 据此回答，并返回前端可以打开的页码。到第三周，我们要能说明哪些问题答得准、引用是否支持回答、时间主要花在哪里，以及一次具体优化带来了什么变化。

职责按[开工会文档](kickoff.md)执行。A 决定页面交互和展示方式，C 负责选取可共享的课程材料、概念图、练习设计和评测汇总。B 负责解析讲义、检索证据、调用模型、返回引用、测量速度，以及约 20 个讲义问题的评测。课件格式、检索方式和基线设计参考[项目提案](project/StudyGraph_Project_Proposal%281%29.pdf)。

## 技术方案

文件是系统输入。课程名称、知识点、页数和参考答案都可以变化。ACS 第一讲用于回归验证。前端接入见[文档 API](document-api.md)。

| 模块 | 当前选型与行为 | 下一项技术验证 |
|---|---|---|
| 导入与存储 | FastAPI multipart 上传，SHA-256 标识内容，SQLite 事务保存原件、页、片段与索引。重复上传复用文档 ID。 | 同名不同内容应生成不同 ID。比较并发导入的耗时。 |
| PDF | PyMuPDF 逐页提取，保留从 1 开始的物理页号，按需渲染 PNG。无文本页可配置 Tesseract OCR。 | 用双栏、扫描页、英文多栏排版检查阅读顺序和 OCR 准确率。 |
| PPTX | python-pptx 遍历文本框、组合、表格和图片，默认返回 HTML 内容预览。配置 LibreOffice 后转 PDF，按页数核对并渲染版式。 | 用真实课件核对字体、图表、空页。旧版 PPT 先另存为 PPTX。 |
| 检索 | 页内切片长 900 字符、步长 800。SQLite FTS5/BM25 按文档取前 k 个片段。英文按词，中文按双字切分。 | 对照英文原词、缩写和同义改写的参考页命中率。若术语改写漏检，比较英文向量检索与 BM25，再决定是否引入融合排序。 |
| 问答 | 直接用英文问题检索，再由 Qwen 基于候选片段用英文回答。返回的引用编号由后端映射到真实页。可用 retrieval_query 指定检索词。 | 测量参考页命中率、模型往返和端到端耗时。当前按单次文档问题检索，多轮上下文和概念映射仍需接入。 |
| 前端 | React + TypeScript 调用 FastAPI，按 preview_url 展示原页。OpenAPI 提供请求与响应类型。 | A 用同一接口接正式页面，C 从页接口取得稳定片段 ID 和原文。 |

当前已用 67 页 ACS PDF 和两页 PPTX 验证导入与预览。英文 Roofline 检索命中第 67 页。真实 GPU 联调也已通过：上传 ACS PDF 后，以中文询问计算强度及带宽受限时的性能上限，接口返回 provider=tacc 和第 67 页引用，两个答案要点均与原文相符。此结果为单题验证，整套评测按下表执行。以下时间表用于团队验收。

## Learning 问答的 Baseline 与 Agent（下一阶段）

**当前实现。** 使用 [earendil-works/pi](https://github.com/earendil-works/pi) 的 pi-agent-core / pi-ai 1.5.2。已接入原生工具调用、最多三次模型调用的循环、讲义检索和读页工具、多轮上下文、流式回答、执行记录和停止按钮。已在 TACC 上验证真实 Qwen 的工具调用。运行方法见 [pi Agent 接入说明](pi-agent.md)，联调数据见 [Agent 评测说明](agent-evaluation.md)。

现有英文单轮问答作为 Baseline：用原问题做一次 BM25 检索，取前四个片段交给 Qwen，返回答案和页码。下一阶段要验证的是：首轮证据只回答了问题的一部分时，追加检索能否补全答案，值得多等多久？

| 模型选择 | B 的后端如何处理 |
|---|---|
| `answer` | 根据已读片段作答。后端检查每条引用的 ID，并映射回讲义原页。 |
| `search` | 模型针对缺少的依据给出英文检索词。后端只查当前讲义，按 chunk_id 去重，把新增片段交回模型。 |
| `abstain` | 讲义依据不足，说明缺少什么，结束本题。 |

每题最多追加两次检索、调用模型三次。遇到重复查询、没有新增片段或用完检索次数，下一次调用只能作答或拒答。最后一次调用直接使用这个限制。连接失败单列为服务错误。

**接口交接。** 现有 `POST /api/ask` 用于单轮 Baseline，Agent 通过 `POST /api/agent/stream` 流式返回答案、引用、实际检索记录、模型调用次数和耗时。Learning 已可切换 Agent 并查看检索记录。Tests 的套题生成与后续反馈接口按下一阶段计划对齐。

**演示验收。** 用一道同时涉及 Amdahl 定律和 Roofline 的问题检查答案能否分别解释串行比例和内存带宽的限制，并用 ACS 第 66、67 页支持这两个要点。再用一道第一页证据就足够的简单题检查能否一次模型调用结束。以实际运行记录为准，允许首轮已找齐证据时直接作答。

## 三周安排

D1 从团队实际开工日算起。以下是 B 的工时预算，每周 16 小时，包含联调、评测和展示准备。

| 时间 | 预算 | B 的工作 | 当天能交付或检查什么 |
|---|---:|---|---|
| D1–D2 | 5 h | 从首份讲义按页提取文本，页内切片。页码从 1 开始，空页保留原编号；同一版本重复解析得到相同的片段 ID。 | 交给 A、C 一份含 `document_id、chunk_id、page、text` 的样例。对照原文件检查两个概念所在页。 |
| D3–D4 | 6 h | 建立关键词检索，将问题、选中概念和命中片段交给现有 Qwen 客户端；从实际送入模型的片段生成引用。记录检索、模型请求和总耗时。 | **D4 三人联调**：A 点选 C 标注的概念，B 返回真实回答和出处。三人打开原页，核对它是否支持回答中的关键结论。 |
| D5–D7 | 5 h | 检查直接提问、换种说法、超出讲义范围和模型连接失败；和 C 走通共享模型入口。参加一份讲义的完整演示。 | A 能区分“材料不足”和“服务失败”。C 能用同一模型入口发一次请求。保留一条可复现的问答记录。 |
| D8–D10 | 7 h | 扩至 2–3 份讲义，补齐约定的 PDF/PPTX 输入；验证不同文件中相同页码能正确区分。处理同一会话里的追问和切换概念。 | 用同一个多轮例子检查“这个上限怎么来的？”是否仍指向上一轮概念。记录关键词漏检的真实例子，对照向量或混合检索的结果。 |
| D11–D14 | 9 h | 固定现有 Baseline，接入 Agent 追加检索与停止条件。和 C 核对约 20 道题的要点与参考页，提前划出保留题。 | D14 用开发题演示一次追加检索和一次直接作答，交付双模式接口、运行记录和评分脚本，再冻结配置。 |
| D15–D18 | 10 h | 对保留题运行正式评测，与 A、C 交叉核对原页。把错误区分为没找到原文、找对但答错、引用不支持、服务失败。 | 将逐题结果和统计交给 C 汇总。选一个失败案例，列出问题、命中原文、实际回答和可能原因。 |
| D19–D21 | 6 h | 整理架构图、测量结果与局限，和彩排使用同一份讲义、同一条演示问题。 | 完成 B 的报告段落和约 3 分钟展示，讲清真实请求经过哪些组件、优化了哪一步、还有什么限制。 |

## 和 A、C 怎么接

- **B 给 A**：沿用 `POST /api/ask`。A 传 `session_id、question` 和可选的 `concept_id`；B 返回回答、证据状态和引用列表。引用定位到文档、片段及页码。证据不足时返回空引用，模型请求失败时返回服务错误。字段对照[接口约定](document-api.md)。
- **B 给 C，C 回给 B**：B 先给逐页片段；C 核验原文，提供概念与片段的对应关系。B 用这份映射处理选中概念后的问题。C 设计练习和评分规则，需要动态生成内容时由 B 提供模型调用方式。
- **三人共同验收**：B 检查引用 ID 和页码确实存在，A 检查点击后打开正确原页，C 与 B 复核原文是否支持答案。页码正确和结论有依据分别记录。

## 约 20 个问题怎么测

已有 [双模式对照脚本](../evaluation/compare_agents.py) 和 [运行与人工判分说明](agent-evaluation.md)，支持独立题、多轮追问、重复运行、跨页要点的来源覆盖和错误记录。候选开发题见 [agent-dev.json](../evaluation/agent-dev.json)，已用真实模型做小样本对照。正式参考要点及保留题由评测组复核后冻结，再运行正式评测。

B 用同一讲义版本、同一模型、同一条预热后的 SSH 连接和相同的首轮检索配置，逐题运行 Baseline 与 Agent。按直接查找、同义改写、跨页综合、证据不足分别汇总。B 和 C 为每个必答要点标注可接受的证据页；跨页题只有在每个要点答对且各有引用支持时才计为整题通过。任一参考页命中仅作为检索诊断。逐题保留两种答案，报告要点答全、引用充分、正确拒答的题数，以及模型调用次数和总耗时。C 汇总保留集结果。

问题覆盖讲义定义、公式计算、跨页证据、承接前文的追问，以及讲义无法回答的问题。每题记录讲义版本、参考答案要点、可接受的证据页；分开发集和保留集后，仅用开发集调整检索和提示词。保留题数量与 C 在首次选题时确定。

| 要回答的问题 | 记录方式 |
|---|---|
| 检索找到了吗？ | 对有答案的题，统计前 k 个片段命中任一参考页的题数 / 有答案题数，写明 k。 |
| 回答和引用可靠吗？ | 分别核对答案关键点、引用位置和原文支持度；对范围外问题单列“正确说明材料不足”的题数。报告分子、分母和失败样例。 |
| 用户等了多久？ | 每题记录检索、模型请求往返、后端总耗时及失败状态。模型往返包含 SSH 和网络时间。记录冷启动与预热状态，比较同批题的中位数和最慢请求。 |
| 优化值得保留吗？ | 前后使用相同问题、模型及运行条件，每次只改一个因素。若检索最慢，先试复用索引；若模型请求最慢，先试缩短输入片段。把节省的时间与答对题数、引用支持题数并排列出。 |

## 检索开发集与复现

[ACS 开发集](../evaluation/archive/legacy/acs-dev.csv) 包含 13 个知识点，每题各有中、英文问法，并标注一页参考原文。该集合用于调试，正式评测需另留题目。

在仓库根目录运行：

```powershell
.\.venv\Scripts\python -m evaluation.runners.retrieval docs/ACS_Lecture_1_2026F.pdf evaluation/archive/legacy/acs-dev.csv
```

脚本在临时 SQLite 库导入讲义，输出每题前四个片段的页码和参考页排名。本次英文问法首位命中 12/13，前四命中 13/13；中文原词前四命中 0/13。这个结果只衡量直接 BM25 检索。本阶段只运行英文题。下一轮用英文同义改写和范围外问题检查召回、引用支持与拒答。

英文问答追加验证（开发集）：[三道改写题与两道范围外问题](../evaluation/archive/legacy/acs-english-challenge.json)。首次真实联调中三道改写题触发引用编号校验错误。将候选片段标为 S1、S2 等字符串，并要求模型原样返回后，同批复测引用页为 57、66、67，两道范围外题均返回 insufficient 和空引用。第二题只回答 10x，数值正确，未解释串行部分的影响。单次复测的检索耗时为 1.46–3.39 ms，模型往返为 4.03–9.48 s。此批用例用于修正提示词，正式评测需使用其他题目。

复现时在真实模型后端导入 ACS 讲义，运行 `python -m evaluation.runners.english_qa http://127.0.0.1:8016 DOCUMENT_ID evaluation/archive/legacy/acs-english-challenge.json`。脚本核对页码和证据不足状态，回答内容按题目中的 expect 另行复核。

**B 对 Tests 的交付。** 接收 C 制定的概念覆盖和题量，为每个概念检索可核验的讲义片段，提供按套生成题目草稿的模型调用，并核验返回的来源 ID。C 负责题组设计、评分和学习记录，A 在独立 Tests 页面呈现题序、提示、进度和整套结果。接口见[套题接口草案](document-api.md#tests-套题接口待开发)。
