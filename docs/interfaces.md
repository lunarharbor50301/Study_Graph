# D1 接口与样例约定（讨论稿）

A、B、C 用同一份讲义走完下面的流程，再确定接口。下表给出建议字段；示例 ID 仅供讨论。实现后以 FastAPI 生成的 OpenAPI 为准，本页保留跨模块约定。

| 操作 | 模块间传递的数据 | 验收 |
|---|---|---|
| 解析讲义 | B 提供 document_id、chunk_id、page、text，可选区域坐标 | PDF 页和幻灯片都从 1 计数；viewer 能从文档 ID 和页码打开原页 |
| 点选概念 | C 提供 concept_id、名称、来源片段；关系包含起止概念、类型和来源，标记是否推断 | A 能显示关联概念，明确区分讲义明示和推断关系 |
| 提问与追问 | A 发送 session_id、问题和可选 concept_id；后端返回回答、引用列表和证据状态 | 直接提问和选概念提问均可用；证据不足时返回明确说明 |
| 请求练习 | C 提供 exercise_id、目标概念、题干；参考答案和评分标准保存在后端 | 对话和 Tests 页面复用同一题目格式 |
| 作答与重试 | 提交 session_id、exercise_id、作答内容；后端生成 attempt_id，保存反馈、提示事件和后续尝试 | 重答产生新记录，仍能找到首次作答及期间使用的提示 |

## 共享样例

先选讲义原页，再写对应的 JSON。建议 examples/ 放一份获准共享的讲义、一条真实原文片段、两个相关概念、一条关系、一组带引用的问答和一题练习。另附一次错误作答、针对该错误的提示和一次重答。固定样例用于开发，正式评测留出另外的题目。

例如，若目标内容出现在示例讲义的第 2 页，回答中的一条引用可写成：

```json
{"document_id": "lecture-01", "chunk_id": "lecture-01-p2-01", "page": 2}
```

B 检查片段确实来自该页，C 用同一片段标记概念来源，A 点击引用打开第 2 页。缺少区域坐标时展示整页。

## 联调时保留的证据

按请求记录会话、所选概念、检索片段、最终引用、处理耗时和错误状态。StudyGraph 和 baseline 使用相同的讲义、检索组件、模型及评测输入。正式评测检查任务完成、引用支持、反馈质量和耗时，并保留至少一个失败案例用于分析。
