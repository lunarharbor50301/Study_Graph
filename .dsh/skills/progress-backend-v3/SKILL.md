# 概念图 V3 后端进度记录

## 何时使用

只要发生下面任一情况，就先更新记录，再向用户汇报：

- 改了 V3 后端代码、配置、提示词、schema 或接口行为；
- 跑了一次真实模型实验，或得到新的耗时、token、节点数、覆盖率、失败率；
- 发现旧记录有事实错误，或实验结论发生变化；
- 前端/测试同学需要知道新的行为、字段、限制或复现方式。

## 唯一写入文件

仓库根目录的 `docs/progress-backend-v3.md`。不要另建第二份进度文件；实验原始 JSON 放在仓库根目录或用例目录，文档里链接它。

## 写之前

1. 先读 `docs/progress-backend-v3.md`，保留已有条目，不覆盖历史。
2. 找到顶部“最后更新”“当前状态”和“给前端/测试的对接摘要”，按本次变化更新。
3. 新条目加在“变更与实验记录”的最上面，日期用 `YYYY-MM-DD`，同一天可按时间或主题分多条。

## 每条必须写清

- **类型**：改动 / 实验 / 修复 / 配置 / 结论更正。
- **范围**：碰了哪些文件、哪个阶段（骨架、分批笔记、覆盖检查、缓存、路由）。
- **实验设置**：provider、模型名、讲义名和 SHA-256 或 doc id、页数、学生要求、缓存开关、并发数、调用上限、重复次数。
- **结果**：实测数字和失败数；明确区分“实测”“估算”“未测”。
- **对前端**：接口/字段/响应结构/等待时间/是否有流式变化；没有变化也要写“无需改动”。
- **对测试**：新增或变化的用例、期望结果、复现命令、已知环境限制。
- **局限与下一步**：这次没回答的问题，不要用推测补成结论。
- **产物**：结果 JSON、日志、脚本、计划文档的相对路径链接。

## 条目模板

```markdown
## 2026-11-18 — 一句话标题

- **类型**：
- **版本/范围**：
- **改动**：
- **实验设置**：
- **结果**：
- **对前端**：
- **对测试**：
- **局限/下一步**：
- **产物**：
```

## 规则

- 只用事实：没有跑过的实验标“未测”，不要写成“实测”。
- 一个条目只讲一件事；代码改动和实验数据分开记。
- 保留失败、超时、部分结果和负面结论；这些对测试最有价值。
- 不在文档里写 API key、token、密码；只写环境变量名。
- Markdown 链接按文档所在目录写相对路径；正文里提到路径时可以写仓库相对路径，例如 `backend/concept_map.py`、`concept-map-v3-deepseek-flash.json`。
- 接口或响应行为变化时，先更新“给前端/测试的对接摘要”，再写日期条目。
- 收尾时更新“最后更新”和“待补实验”，并在最终回复里用一句话说明该文档已更新。

## 完成检查

- `docs/progress-backend-v3.md` 顶部信息是最新的；
- 新条目有日期、设置、实测/估算标记、前端和测试影响；
- 旧条目没有被删除或改写（纠错时标注“更正”）；
- 文档里没有密钥；
- 结果文件路径能打开。
